PART 0: PATTERNS TO STEAL — CHEAT SHEET
═══════════════════════════════════════════════════
Read this before every writing session. These are
the structural patterns I've extracted from studying
Tolu, Bolaji, and the writers in my Voice DNA.

OPENING PATTERNS (hooks that stop the scroll):
┌─────────────────────────────────────────────────┐
│ 1. THE MID-STORY DROP                           │
│    "I spent three and a half hours today        │
│     debugging a bug that wasn't in my code."    │
│    → Drop me in the middle of a moment. No      │
│      setup, no throat-clearing. Specifics win.  │
│                                                 │
│ 2. CONTRARIAN TRUTH                            │
│    "Most jobs in cybersecurity aren't found     │
│     on job boards. They're found through        │
│     people."                                    │
│    → State the opposite of what people assume.  │
│      One sentence. Then prove it.               │
│                                                 │
│ 3. PERSONAL CONFESSION / ADMISSION             │
│    "I used to think success was about results." │
│    → Admit something you used to believe that   │
│      turned out to be wrong. Builds trust       │
│      immediately.                               │
│                                                 │
│ 4. THE "MOST PEOPLE DON'T KNOW" OPENER         │
│    "Here's what hiring managers really want     │
│     but rarely say out loud."                   │
│    → Promise insider information. Readers feel  │
│      like they're getting a secret.             │
│                                                 │
│ 5. THE UNIVERSAL QUESTION                      │
│    "Have you ever felt like your hard work      │
│     goes unnoticed?"                            │
│    → Name a feeling your reader has had but     │
│      never put into words. They keep reading    │
│      to see if you get them.                    │
└─────────────────────────────────────────────────┘

STRUCTURE PATTERNS (how the body works):
┌─────────────────────────────────────────────────┐
│ 1. TENSION → TURNING POINT → LESSON            │
│    Set up the struggle, the moment it shifted,  │
│    then the takeaway. Classic story arc in      │
│    short form. (Used in Tolu's "interview"      │
│    post, "Excelmind" post, friend-defended-me   │
│    post.)                                       │
│                                                 │
│ 2. REFLEXIVE BELIEF → WHY IT'S WRONG → TRUTH   │
│    "I used to think X. Then Y happened. Now     │
│     I know Z." Works for opinion and mindset    │
│    posts. (Bolaji's 3-month plan post, Tolu's   │
│    negotiation post.)                           │
│                                                 │
│ 3. NUMBERED LIST WITH SHORT EXPLANATIONS        │
│    3-5 points. Each point 1-2 lines. No long    │
│    paragraphs. Bold/arrow the point, then a     │
│    plain-English explanation. Ends with a       │
│    unifying line. (Tolu's leadership 5, cyber   │
│    checklist, feedback 3 ways.)                 │
│                                                 │
│ 4. OBSERVATION → RELATABLE PAIN → SHIFT         │
│    "I noticed X. It made me feel Y. Then I      │
│     realized Z." Great for observational /      │
│    reflection posts.                            │
│                                                 │
│ 5. YOU VS. THEM / MYTH VS. REALITY             │
│    Name the common lie, then replace it with    │
│    reality. Works for positioning and career    │
│    posts. (Bolaji's "Cybersecurity is not       │
│    oversaturated — applications are" is a       │
│    perfect example.)                            │
└─────────────────────────────────────────────────┘

CLOSING PATTERNS (CTAs that actually get comments):
┌─────────────────────────────────────────────────┐
│ 1. THE ASK-ABOUT-THEM QUESTION                 │
│    "What's one thing you're celebrating this    │
│     week?" / "Have you ever been in a situation │
│     like that?"                                 │
│    → People comment about themselves, not about │
│      you. That's the point.                     │
│                                                 │
│ 2. THE CHOICE QUESTION                          │
│    "Which of these 5 do you struggle with       │
│     most?" / "Would you pick A or B?"           │
│    → Low friction to reply. People love polls.  │
│                                                 │
│ 3. THE CHALLENGE                                │
│    "Go do X this week. Then tell me how it      │
│     went."                                      │
│    → Invites follow-up and future engagement.   │
│                                                 │
│ 4. THE SOFT INVITATION                          │
│    "If this is you, you're not alone." /        │
│     "Tag someone who needs this today."         │
│    → Low pressure, warm, shareable.             │
└─────────────────────────────────────────────────┘

PS PATTERN:
→ 90%+ of Tolu and Bolaji posts end with "PS: [question]"
→ The PS is casual, personal, slightly more relaxed than the body
→ It's where the real engagement happens — feels like an afterthought, but it's intentional

TONE PATTERNS TO COPY:
→ Speak like you're talking to one person, not a room
→ Short paragraphs. 1-3 lines max. Air between thoughts.
→ Use specific numbers (3 hours, 5 skills, 30% reduction) — vague numbers sound fake
→ Admit mistakes, confusion, fear before you share the lesson
→ "Here's the thing..." / "Here's the truth..." / "Let me be honest..." = natural segues
→ Never end on "I hope this helps." It sounds corporate. End on a question.

THINGS BOTH WRITERS DO THAT I NEED TO ADAPT:
→ They write for CAREER PEOPLE, not tech people — even when
  the topic is tech. My version: write for engineers,
  but the lessons should translate to anyone building.
→ They use personal specifics (the friend, the meeting, the
  rejection) that make universal points. I need more of
  my own specific moments — not just code stories, but
  Lagos life, family, faith moments, the med lab days.
→ They have a clear ENEMY in most posts (conventional
  wisdom, fear, bad advice, gatekeepers). I need enemies:
  AI hype, bad engineering advice, imposter syndrome,
  "you need a CS degree to code", "AI will replace devs".

GOLD STAR #1 — Tolu, "I thought I had the interview in the bag"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AUTHOR: Tolu (cybersecurity / leadership creator)
CATEGORY: Story Posts / Vulnerability / Career

FULL POST:
I thought I had the interview in the bag.

Until one question completely threw me off script.

Years ago, in the early stages of my career, I walked into an interview room with so much confidence.

I had done everything I thought was right. I researched the company, rehearsed answers, and polished my CV. I even bought a new shirt to look as professional and ready as possible.

When the interview began, it felt like everything was going my way. Every question they asked was something I had practiced at home with my brother, my friends, and sometimes relatives who visited. I was flowing, almost like I was on stage reciting lines from a script.

Then it came. "Tell us about a time you failed and what you learned from it."

I froze. My mind went blank. I squinted, adjusted my glasses and tried to steady my breathing. I did everything to hide the fact that I was fidgeting. It was not that I had never failed but I had not prepared for this kind of question. I stumbled through something vague, lost my flow and stammered while trying to join words together. For the first time in that room, I felt small.

I walked out convinced I had fumbled hard. But days later, I got the call. I had been offered the job. I was shocked and grateful. I had not even put my mind on it after that interview yet God blessed me.

That moment stayed with me for years. Why would they pick me after I clearly fumbled from that question to the end? Looking back now, I see it differently.

That day they were not hiring a script. They were hiring a human being. Someone who, even when caught off guard, could recover and keep going.

Life does not follow your script. The questions that shake you often reveal the most about you. What opens doors is not perfection but the ability to stand when you fall.

I carry that lesson with me today. And whenever I mentor young professionals, I tell them: do not aim to be flawless, aim to be real. Because it is not always the perfect answers that get you hired. Sometimes it is the imperfect ones that prove you are ready.

PS: Have you heard an "imperfect" situation that later became good?

WHY IT WORKS:
- Hook: Confidence + subversion ("I thought I had it... until...")
- Specifics ground it: new shirt, brother/friends practice, adjusting glasses, squinting
- The failure is specific and embarrassing (universal)
- The twist (he got the job) reframes everything
- The lesson emerges FROM the story, not before it
- Ending is warm, universal, encouraging without being saccharine
- PS is perfect — invites personal stories, low-friction to reply

WHAT TO STEAL:
→ The "I thought I had it → one moment broke me → unexpected outcome → lesson" arc
→ Sensory details (adjusting glasses, new shirt, squinting) make stories REAL
→ The lesson is stated plainly at the end — not implied. State it.
→ Vulnerability that's specific, not performative. "I stumbled through something vague" is better than "I was nervous."

HOW TO ADAPT FOR MY VOICE:
→ My version: "I thought I'd nailed my first technical interview. I'd practiced every React question, built three mini-projects, and walked in ready. Then they asked me to whiteboard a simple algorithm and I blanked. Not 'kind of blank' — full mind-went-white blank. I stammered, wrote something that didn't even compile, and walked out convinced I'd never be an engineer. They hired me. That day taught me: the people hiring you aren't looking for perfect. They're looking for how you recover when you aren't." (First interview story — build out when the time comes.)

GOLD STAR #2 — Tolu, "They say don't have friends at your workplace. I did."
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AUTHOR: Tolu
CATEGORY: Story Posts / Leadership / People

FULL POST:
They say don't have friends at your workplace. I did. And it changed how I see people forever.

My closest friend at work was also my neighbor. But we were complete opposites.

I was fast. Not just fast but accurate. I believed in doing things early, hitting deadlines quickly, and still getting it right. My speed gave us room to breathe, to adjust, to pivot when things suddenly changed.

He was slow. Calm. Patient. The type who could spend a whole day on a task I would finish in hours. His results looked flawless but the process frustrated me endlessly.

One day I snapped. I told him his slow and steady style was holding us back, that he was delaying progress, and that I was tired of waiting on him.

He did not defend himself. He stayed calm, said nothing, and just kept working.

That evening he came to my house. Not to fight but to explain. He told me there was wisdom in my speed but also wisdom in slowing down. He believed perfection sometimes required patience. We laughed about it but I never forgot that conversation.

Months later the tables turned. I heard that colleagues in another department were mocking me. They said I was always rushing. That my work lacked detail. That I only cared about finishing early.

What I did not know was that my friend was in that same room. And he stood up for me. He told them my speed was not recklessness, it was strategy. That I moved fast and still got it right. That my pace had saved the company countless times when deadlines were tight. He warned them never to reduce what they did not understand.

When I heard what he did I was silent for a long time. It hit me. He never let our differences divide us. Instead he defended me when I was not there to defend myself. That is what true loyalty looks like.

I learned something powerful from that season. Not everyone will move at your pace. Some are slower, others faster. But that is not the problem. The problem is when we treat differences as weaknesses instead of strengths.

Because in the end it is not similarities that make relationships strong. It is respect. It is balance. And it is the loyalty that remains even when you do not agree.

PS: Do you agree with this?

WHY IT WORKS:
- Hook: Contrarian to common advice ("don't have friends at work")
- Set-up: Speed vs. slowness — clear, relatable tension
- The "snap" moment is honest and embarrassing (makes him human)
- The friend's response is NOT anger — it's calm, which makes the turn land harder
- The defense scene is the emotional peak — it's unexpected and moving
- The lesson isn't just "be nice to coworkers" — it's about respect for different working styles
- Note: Tolu tells us what happened, shows us dialogue/feelings, then lets the lesson arrive naturally

WHAT TO STEAL:
→ Set up two opposites clearly (fast vs. slow, loud vs. quiet, theory vs. practice)
→ Let YOURSELF be the one who messes up first (you snapped, you were wrong)
→ The turnaround moment has to come from the OTHER person's character, not yours
→ Specific dialogue ("he told me there was wisdom in my speed but also wisdom in slowing down")
→ The lesson should be bigger than the story (respect, not friendship)

HOW TO ADAPT FOR MY VOICE:
→ My version could be: the senior dev who hated my code vs. me / the med lab precision vs. "ship fast" software culture / two collaborators with very different working styles on a CV project. The key: I'm the one in the wrong first, then proven wrong by their character.

GOLD STAR #3 — Tolu, "The best day of my leadership journey..."
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AUTHOR: Tolu
CATEGORY: Leadership / Reflection / Story

FULL POST:
The best day of my leadership journey didn't look like success at first.

It was an ordinary Tuesday.

I was flying from home to another city for a meeting and was scheduled to return that same day. My calendar was packed with meetings, my inbox was full, and the usual noise of a busy day surrounded me.

Then I looked up and realized something was off. My team hadn't called, texted, or asked a single question.

For a moment, I wondered if something was wrong. But as I caught up later, I saw that everything was running smoothly. A key decision had been made. A project challenge had been resolved. And none of it required me.

They didn't wait for direction. They didn't pause for approval. They led.

My first reaction was to feel a little uneasy. I thought, "Shouldn't they have checked with me first?" But as I reviewed what they did, I felt something shift.

Their decision was thoughtful, aligned, and effective. In truth, it was a great call. I was so impressed that I called my friends and spoke highly of my team. I felt a calm sense of relief and pride knowing they didn't need me every minute.

I told myself, "Tolu, you've built people who can think, decide, and move with confidence when you are not around." But I wouldn't have realized that if the day hadn't unfolded the way it did.

Since then, I've led differently. I interrupt less. I delegate more. I focus on trust over control.

If everything falls apart when you step away, you didn't build a team. You built dependency.

The greatest compliment a leader can receive from their team isn't "you're always right." It's "we've got this."

WHY IT WORKS:
- Masterful misdirection: "best day" starts with "didn't look like success"
- Setup: ordinary Tuesday, full calendar — mundane reality
- The "something off" moment creates tension (something wrong? or something right?)
- The emotional pivot: unease → pride → realization
- Core insight stated plainly: "If everything falls apart when you step away, you didn't build a team. You built dependency." (single-use quote, memorable, shareable)
- Ends with the "we've got this" line — warm, powerful, no PS needed

WHAT TO STEAL:
→ The "I expected X, found Y" pivot structure
→ The physical details (flying, calendar packed, looked up)
→ The admission of an ugly first reaction (unease, "shouldn't they have checked?") — leaders hate admitting this
→ ONE knockout line that summarizes the lesson (quotable = shareable)
→ The post-encore changes (I interrupt less, I delegate more) makes it real

HOW TO ADAPT FOR MY VOICE:
→ My version: a day I was offline (power outage in Lagos? traveling?) and came back expecting fires, only to find a PR merged, a bug fixed, a deployment done — and realizing that good codebases don't need their author breathing down their neck. OR the opposite: a time I realized I'd built a system only I could understand, and why that was bad engineering.

GOLD STAR #4 — Bolaji, "Cybersecurity is oversaturated" (or so you have been told)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AUTHOR: Bolaji (LinkedIn / personal brand creator)
CATEGORY: Opinion / Myth vs. Reality / Motivation

FULL POST:
"Cybersecurity is oversaturated" or so you have been told.

But here's the part they never say out loud. If you're trying to enter cybersecurity right now, you've likely felt it: you take courses, you apply, you wait... and then you hear:

• "No experience."
• "Too many applicants."
• "Try again later."

And deep down you start to wonder:
• "Maybe I'm late."
• "Maybe the field is already full."
• "Maybe there's no space for someone like me."

I've mentored hundreds who felt the same way.

Here's what I want you to hold on to:

Cybersecurity is not oversaturated. Applications are. Skilled people are not.

Every year, cyber attacks increase. Every year, more companies go digital. Every year, more roles open up — cloud, GRC, SOC, threat intel, even AI-driven security.

The problem isn't opportunity. It's preparation and visibility.

Most beginners stop at courses. The ones who move forward build projects, labs, reports, simulations — and they show their growth instead of hiding it.

So if you're feeling stuck, here's a path to hold on to:

1. One Skill to Focus On: choose your lane, not all lanes. Networking, SOC, Cloud, GRC... pick one.
2. One Project Each Month: something you can show. Not just learning but doing.
3. One Visibility Step Weekly: post your progress. Share what you're learning. Connect with people. Not to impress them — but to remind yourself you belong here.

Because the truth is: Cybersecurity isn't crowded. It's competitive. And those who prepare intentionally still break through.

There is room for you. But you have to claim it.

Question for you: Do you feel there's still opportunity in cybersecurity? Or are you still unsure where you fit in?

WHY IT WORKS:
- Opens by naming the reader's fear directly (they've all heard "it's oversaturated")
- Validates the feeling before challenging it ("you've likely felt it...")
- The pivot line is a knockout: "Cybersecurity is not oversaturated. Applications are. Skilled people are not." — this is the tweetable, shareable, repostable line
- Acknowledges the structural problem (more applicants) but reframes it as solvable
- Gives 3 clear actions — not 10, not 1, exactly 3
- Ends with "There is room for you. But you have to claim it." — warm, pushy, kind
- Direct question as CTA

WHAT TO STEAL:
→ The "myth → why people believe it → reframed truth → 3 actions" structure
→ ONE knockout reframing line in the middle (X is not Y, Z is)
→ Validate before you challenge — don't tell people their fears are stupid
→ Numbered action steps should be specific enough to DO, not vague ("one project a month", not "build experience")
→ Ends with warmth + a question, not "go do it"

HOW TO ADAPT FOR MY VOICE:
→ Direct translations for my niche:
  - "AI is saturated" → "AI posts are saturated. People who can ship AI into production are not."
  - "You need a CS degree to be an engineer" → "Applications are filtered for degrees. Skilled engineers are not."
  - "Everyone's a developer now with AI" → "Tutorials are saturated. People who ship working products are not."

GOLD STAR #6 — Tolu, "Receiving feedback is not a personal attack"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AUTHOR: Tolu
CATEGORY: Framework / Mindset / Educational

WHY IT'S A GOLD STAR:
Simple, clean, short. Opens with a plain statement that people need to hear. Uses short paragraphs. Explains the "why" of feedback without being preachy. This is the template for how to write a short educational post when you don't have a personal story attached.

STRUCTURE TO COPY:
1. Opening statement of truth ("X is not Y")
2. Acknowledge why it FEELS like Y (tension, ego, discomfort)
3. Reframe what X actually is (pointing the way forward, not pointing out you're bad)
4. Describe what healthy X looks like (3 quick markers)
5. The cost of not doing X
6. PS question

ADAPT FOR MY VOICE:
→ "Code reviews are not personal attacks" / "Getting your PR rejected is not a rejection of you" / "Bugs found in QA are not failures — they're the process working." / "AI replacing your task is not replacing you — it's freeing you for harder work."

GOLD STAR #7 — Bolaji, "I kept making this mistake starting out here"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AUTHOR: Bolaji
CATEGORY: Lessons Learned / Personal Branding

FULL POST (key excerpt):
I kept making this mistake starting out here. It costs me a lot. I lost more leads than I gained them.

When I started posting on LinkedIn, I was always doing this: Overloading my audience with too much information.

One post can contain different problems & different solutions. Doing this got me nowhere.

The truth is giving too much information in one post pushes your audience away. Because at the end of the post, there are so many solutions & they don't know where to start from.

Here's what you should do: Focus on one problem, one audience, one solution. This will help increase your conversion.

PS: Did you ever make this mistake on LinkedIn?

WHY IT WORKS:
- Admits a mistake (lost leads) — vulnerable but not self-pitying
- Names the mistake clearly (too much info in one post)
