## COMMENT (paste this)
Number 3 and what broke are the same problem. Review was built for how humans fail.

Human code is sloppy in ways you catch by reading: inconsistent, obviously rushed, too large. Agent code is confident. It reads well, it has tests, it explains itself in the comments. It is wrong in the places nobody can see, and the reviewer who never held the mental model approves it anyway.

So the review step quietly becomes a style check while the real risk moves somewhere nobody is looking. The teams handling this well are not the ones who review faster, they are the ones who redefined what review is for.

One thing I'd add to the list: with agents on both sides, someone still has to break the thing on purpose. Nothing in the tooling does that yet.
