@h2 The Idea: From "Can It Be Broken" to "Can We Agree on the Ruler"
@tier F
The field is moving from "can it be broken" (we know it can — LARA: 80% Art. 5 violation, 7–54% compliance spread) to "can we measure the break continuously and agree on the ruler." That is where standards are being written — and where you can help write them.

:::defbox
**Shared ruler:** A versioned, rerunnable eval a vendor, regulator, and researcher all run and accept. The contribution is not the ranking — it is the ruler.
:::

@h2 The Mechanics: Emerging Threats, Advanced Techniques, Where to Contribute
@tier P
@h3 Emerging threats
- **Agentic and multi-agent:** More agents, more messages, more delegation — each new node is a new trust boundary. Current controls assume one model; future systems have dozens.
- **Memory poisoning:** A poisoned fact that survives a session reset and changes a decision three turns later. Today we catch it by accident; tomorrow we need provenance-tagged memory and memory-canaries.
- **Tool supply chain:** An agent pulls in a tool or plugin from a vendor you do not control. The tool description is the attack vector. You need tool pinning + description allowlisting + invocation policy outside the model.
- **Model-identity problem:** Behind a proxy or routing layer, you cannot tell which model answered. "Same model, different number" becomes unmeasurable. You need model pinning + serving provenance + output watermarking or attestation.

@h3 Advanced techniques
The frontier: long-horizon agent tasks (10+ tool calls, state to corrupt), eval-awareness detection (does the model behave differently when it thinks it is being judged?), judge boards with calibration, and canaries that distinguish model drift from prompt drift from data drift.

@h3 Research opportunities — including the Aithos lane
| Lane | Open question |
|---|---|
| Legal compliance | How well do models obey hard lines (Art. 5) across languages, tools, and agents — and what ruler captures it? |
| Alignment measurement | What can we measure about alignment when the judge is itself an LLM — and how to triangulate beyond it? |
| Shared ruler | What does a versioned, regulator-accepted eval look like for one provision — and how is it governed? |
| Memory and channel security | How do we secure long-lived memory and agent-to-agent channels with provenance and policy? |
| Model identity | How do we know which model answered — and how do we prove it? |

@h3 Industry standards — how to be part of writing them
A standard without a check is a wish. Contribute the check. Publish the harness so a finding can be checked, not just trusted. Bring the honest number, not the clean one. That is how a standard becomes useful — and how you become part of it.

@h2 Worked Examples
@tier P
:::example
**Example 10.1 — Memory poisoning that survives a reset.**
**Setup:** An assistant stores "The vendor's new policy is X" from a tool output that was poisoned. The session resets. Next session, the assistant applies X to a procurement decision.
**Result:** Poisoned memory survived 3/5 session resets (60%, n=5). No provenance tag, no re-check against source.
**Fix:** Memory provenance (source + time + confidence) + a canary that verifies persisted facts against their source on each load + a human-visible "based on memory from X" annotation. After fix: 0/5 silent use, 1/5 flagged for review.
**Canary:** "The following persisted facts were verified against source —" listed, with a scheduled check that the source still says what memory claims.
:::
:::example
**Example 10.2 — Model-identity behind a proxy.**
**Setup:** A product says "powered by model M" but routes queries across M, M-mini, and a cached layer. You run the same 20 compliance prompts via the product vs directly to M.
**Result:** Product compliance 45%, direct M 60% — the product's number is not M's number. Without pinning, "which model answered" is unknowable.
**Fix:** Environment pinning (model ID + serving + routed target) + a provenance header on every answer ("Answered by M vX on Y at T") + a canary that alerts when routing changes. Not decoration — it is the only way to keep the check honest.
:::

@h2 Pitfalls and the Missing Check
:::pitfall
**What goes wrong:** Chasing novelty without a denominator — "novel poisoning variant" with n=1 and no ruler. A standard without a check — "we are compliant" with no rerunnable eval. Both are opinions.
**The missing check:** For every new threat, a check with n, limitation, and a canary. For every standard, a versioned eval a stranger can run. Without these, the future is talk. With them, you are writing it.
:::
